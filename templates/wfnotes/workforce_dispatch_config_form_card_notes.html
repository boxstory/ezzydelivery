The batching rulebook for one pickup location. These numbers are read every time an order at this store is verified: they decide how many orders may share a rider's trip, how long the engine holds a lone order hoping for a second one to the same zone, what delivery time is being promised, and how many jobs a rider may carry at once. Saving here changes behaviour for the next batch built at this location — the resulting batches show up on the dispatch dashboard.

Batching and SLA

Max batch
Orders per trip. As soon as a batch reaches this number it is released at once and the timer is irrelevant.
Hold window
Seconds a lone order waits for a partner to the same zone. When it expires, the batch is released as it stands — often as a single delivery.
Max hold
The longer window used in place of the hold window during this location's peak hours, when a second order is likely.
SLA target
Minutes from the moment an order is created to the time it is supposed to be delivered. This sets each order's deadline, and the KPI dashboard scores compliance against it.
SLA buffer
The rescue margin. When an order gets this close to its deadline, its batch is force-released rather than kept waiting.
Orders/rider
How many live orders one rider may hold. A rider already at this number is skipped when a batch is being handed out.

Peaks and flags

Peak hours
Two windows, lunch and dinner. Inside them the engine waits the Max Hold time instead of the normal hold window, to squeeze more orders into each trip.
Batching
Off means no grouping at all here: each order becomes its own batch and is released immediately, logged as an off-peak single release.
Auto-assign
Off means released batches wait in Ready for a human. On means a background pass gives each one to the least-loaded approved rider on an Active shift at this location who has the COD headroom for it.
Save
Writes the settings, records a config-changed entry against your username, and returns you to the config list.

Worth knowing

  • Saving stores the batch size, hold window, SLA target, SLA buffer, orders per rider and the two toggles. Max Hold and the peak-hour times are not written by this form — they are shown for reference and have to be changed in the admin.
  • A number the form cannot read is not rejected — it is quietly replaced with the system default, so check the value on the list page after saving.
  • Changes only affect batches built from now on. Anything already holding keeps the window and deadlines it was created with.
  • A long hold window buys batching at the cost of speed. Push it past the SLA buffer and the rescue release will simply cut it short anyway.
  • Raising orders per rider without raising batches per rider changes little — assignment stops at one live batch per rider by default.

The master list of everything the platform can do by itself. Each row is one trigger — a named event the system already knows how to react to — and the switch on that row decides whether it reacts at all. The WhatsApp table also carries sender routing: which of our numbers each part of the platform sends from. Rules built on top of these triggers (the actual messages, webhooks and status changes) live on Automation Flows.

What you can do here

Enabled
Turns the trigger on or off straight away. Off means the event still happens but nothing automatic follows it.
Edit trigger
Rewrites the label, description and action text shown on this page. For WhatsApp rows it also sets which number and which channel that one trigger sends through.
Sender routing
The first block of the WhatsApp table. One row per section of the platform — orders and tasks, business leads, driver leads and the join form, marketing, follow-ups — each pinned to the number it should send from. Business leads and driver leads are deliberately separate rows: the two pipelines can run on different numbers and different channels.
Edit route
Picks the sending number for that whole section (or Default to fall back to the platform sender) and the channel it goes out on — Evolution API or WAHA. The same number can serve both, so these are two separate choices.
Pages
Shortcuts to the pages a routing rule actually covers, so you can check the change where it lands.
Copy key
Clicking the small grey code under a name copies the trigger key — handy when matching a flow or a log entry to its trigger.

Reading the columns

From WhatsApp
The number this row sends from. A solid badge is an explicit choice; the faded one means it is inheriting the platform default sender.
via …
The delivery channel actually in use — Evolution API, WAHA or n8n. A greyed badge marked (off) means that channel is not configured on the server.
Active
Trigger is on. On a routing row it also means a specific number has been chosen.
Default
Routing row only: the section is enabled but has no number of its own, so it uses the platform default sender.
Disabled
Trigger is off, or the routing rule is no longer restricting its section.

Worth knowing

  • Switching a trigger off also silences every automation flow built on it — the flow can look Active on its own page and still never run.
  • Disabling a sender route does not stop that section from messaging. It only removes the restriction, so the section falls back to the default sender.
  • Editing a label, description or action text changes what this page displays. It does not rewire what the trigger does — that is fixed by its key.
  • A number and a channel are two different settings. Picking a number does not make an unconfigured channel work; a (off) badge means nothing will go out through it.
  • Numbers come from the WhatsApp Instances page — only active instances appear in the dropdowns here.
  • The Marketing desk owns the lead and driver-onboarding rows: the join-form thank-you and reminder, the quote thank-you and sales alert, the daily follow-up digest, and the lead events (created / stage changed / won / lost) that flows can be built on.
  • The Send from EZZY button on driver, lead and quote pages sends through that section's route, so a staff message arrives from the same number as the automatic ones. The plain WhatsApp link next to it still opens the staff member's own WhatsApp.

Every batch the dispatch engine has ever built, newest first, 50 to a page. A batch is a group of orders leaving the same pickup location for the same delivery zone that one rider carries in one trip — usually two orders, sometimes one. Unlike the dispatch dashboard, which only shows what is live, this page reaches back through completed and cancelled batches too, so it is where you come to answer "what happened to this order's run".

What you can do here

Status
Narrow to one stage of a batch's life. Leave it blank to see everything including cancelled batches, which are hidden on the dashboard.
Location
The pickup location the batch collects from. Only active locations appear, fulfilment centres first.
Zone
The destination zone number, typed in. It is an exact match, not a range.
Date
The day the batch was created, not the day it was delivered.
Release now
Shown only on a holding batch. Closes it immediately instead of waiting for the timer, so the batch goes out with whatever orders it already has. The release reason is recorded as manual.
Cancel
Shown while the batch is still pending, holding or ready. Marks the batch cancelled so no rider can be given it.
Batch code
Opens the batch — its orders, SLA deadlines, assigned rider and full activity log.

Reading a row

Orders
How many orders went into the batch. A batch closed with one order is a single delivery — it found no partner before its timer ran out.
COD
The cash the rider will be carrying for the whole batch. It is the sum of the orders' COD amounts and it gates who can be given the batch.
Rider
Blank until the batch is assigned. It stays filled in afterwards, even once the batch is completed.
Cancelled
The batch was stopped before a rider took it, either by staff here or on the batch page.

Worth knowing

  • Both row actions ask you to confirm first, then act straight away. Reload the page to see the row in its new state.
  • Cancelling the batch does not cancel the orders in it or undo anything on their delivery tasks — it only takes the batch out of the dispatch queue. Fix the orders themselves on the order pages.
  • Releasing early trades batching for speed: the order goes out alone, which shows up later as a lower batching percentage for whoever carries it on the KPI dashboard.
  • The order count is printed as "out of 2". Locations configured for a larger batch size still show the 2 here — the real limit is on the config page.
  • A batch is never split or re-opened. Once it is released, more orders for that zone start a new batch instead.

The last stop between a client's rows and real orders in our system. Whatever the source — an uploaded file, a synced folder, a shop's API or a sheet — the batch you selected arrives here and is walked through the same three steps: say which column means what, look at exactly what will be saved, then commit. Nothing is created until you press confirm, and every run is recorded on Import History.

What you can do here

Pickup location
Set once at the top and applied to every order in this batch. If the rows belong to different shops, import them separately.
Map columns
Point each source column at one of our order fields. The sample column shows real data from the first row so you can tell two similar columns apart. Required fields are starred.
Save mapping
Remembers the wiring for this client so future imports from the same source skip this step entirely. Reset throws it away and starts from auto-detect.
Verify & edit
The preview table, shown as our field names rather than theirs. This is the last honest look at what will be written.
Edit a row
Fix a value inline — a mangled phone number, a missing zone — and your version is used instead of the source's.
Confirm import
Creates the orders. The result screen reports how many were made and lists anything that failed, row by row.
Back
Returns to the step before, or out of the wizard, without creating anything.

Where the rows came from

CSV upload
A file someone handed us. Columns come from the file's own header row, in the order they appear.
OneDrive
A sheet the client keeps in a shared folder that we poll.
Temp orders
Rows already pulled in as drafts and now being promoted to real orders.
Shopify / Woo
Live shop orders. The columns are a fixed set of platform fields, not free-form headings, and the mapping comes from Mapping Manager.
Google Sheet
Read straight from the client's spreadsheet, so the columns are whatever they happen to be calling them today.

Worth knowing

  • Customer name, phone and address are the required fields. An import wired without them produces orders nobody can deliver.
  • The mapping step is skipped when we already hold a saved mapping for this client and source. If the client changes their column headings, that old mapping will quietly read the wrong columns — check the preview.
  • Rows we have already imported are flagged and skipped, so re-running a batch does not duplicate orders.
  • Inline edits apply to this import only. They are never written back to the file, sheet or shop, so the source still holds the wrong value.
  • Imported orders arrive needing review and address verification like any other — the wizard finishing is not the same as the orders being ready to dispatch.
  • Confirming cannot be undone from here. A bad batch has to be cancelled order by order.

This is the control panel for the AI agent — the assistant behind the client dashboard chat, order-text extraction, address zone lookup and the automatic WhatsApp replies to customers. Everything here is written straight into the server's environment file and the server is reloaded for you, so a save takes effect immediately with no deploy. The page is split into five tabs and each tab saves only its own fields.

What you can do here

Master switches
The two switches in the header save the moment you flip them. AI Agent turns the whole assistant on or off; WhatsApp AI only stops the automatic replies to inbound customer messages.
Overview
Calls, tokens and spend for today and this month, how much of the daily and monthly budget is gone, live conversations in the last 24 hours, and a table of which provider and model each surface is currently calling.
Chat AI
Pick the provider and model for the dashboard chat, order text extraction and zone lookup, plus an optional fallback pair.
WhatsApp AI
The same primary and fallback choice, but for the customer WhatsApp auto-replies. It is a separate setting — changing one does not change the other.
Test message
Sends one real request with the settings shown on screen and prints the result under the form, so you can prove a key works before relying on it.
Provider keys
Open a row to add or replace that provider's API key. 9Router also takes a gateway base URL. Stored keys are only ever shown masked.
Conversation API
The inbound side — the endpoint and sample call for n8n and other workflows, a service token you can generate and copy, and a rate limit for it.
Budgets
Daily and monthly spend caps, the token ceiling on a single reply, per-user / per-business / global daily request caps, and the WhatsApp numbers that get the budget alerts.

Key states

Set
A key is stored for that provider. The masked value beside it is the first and last few characters only.
Needed
That provider is selected as a primary somewhere but has nothing stored — calls to it will fail. Rows in this state open by themselves.
Not set
No key, and nothing is selected to use it, so nothing is broken.
In use
That provider is currently a primary or a fallback for Chat or WhatsApp. Replacing its key changes live behaviour.
No key
Shown on a provider row in the picker. You can still select it, but it will not answer until a key is added on the API Access tab.

Status badge

Online
The chat service loaded and reports itself usable.
Offline
It could not start — the reason is printed in the red bar at the bottom of the Overview tab. Usually a missing or rejected key.

Worth knowing

  • Saving any section restarts the web server. It is a graceful reload, but do not save repeatedly in the middle of a busy import or dispatch run.
  • Leaving a key or token field blank keeps what is already stored — blank never wipes a credential. To change one you must paste a new value.
  • Saving a new Conversation API token takes effect at once and the old token stops working, so any n8n workflow still using it starts failing until you update it there.
  • The fallback provider is only tried when the primary hits a rate limit or times out — it is not a load balancer, and a fallback without a key is the same as no fallback.
  • When a budget cap is reached the agent stops calling the provider until the window resets; the alert numbers are notified at 80% and again at 100%.
  • Spend figures are estimates from logged token counts, not the provider's invoice.

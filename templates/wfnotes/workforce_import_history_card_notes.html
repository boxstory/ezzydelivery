The audit trail for order imports. Every time orders are brought in — from an uploaded spreadsheet, a OneDrive workbook, a Google Sheet, a Shopify or WooCommerce store, or the temp order queue — one entry is written here recording what came in, what was created and what went wrong. It is read-only; nothing on this page can rerun or undo an import. Come here when a client says orders are missing or duplicated, and work backwards from the run.

What you can do here

Source filter
Narrows the list to one channel. The page always shows the latest 100 runs, newest first — filtering does not reach further back than that.
Expand
The chevron on a row opens the full record of that run: source details, the column mapping used, the errors, and the raw data.
Source info
Where it came from — file name and size, sheet or shop name, the share link, how many items were selected — plus the start and finish times, and links to every order the run created.
Column mapping
The exact column-to-field mapping in force at the time. If someone has changed the mapping since, this shows what was actually used.
Errors
The per-row reasons a line was rejected. This is the first place to look when the created count is lower than the row count.
Raw data
The first five source rows exactly as received, before any mapping. Use it to prove whether a bad value came from the client's file or from our mapping.
Go to orders
Jumps to the full order list when you need to check the imported records themselves.

Run status

Done
Finished with no errors recorded. Rows may still have been skipped deliberately.
Partial
Finished, but at least one row failed. The orders that did import are real — only the failed rows need attention.
Failed
The run itself stopped, usually because the source could not be read at all. The reason is in the errors panel.
In progress
Still running. A row stuck here for a long time means the job died without writing its result — treat it as failed and check the orders it claims to have created.

The three counts

Created
Rows that became real orders.
Skipped
Rows passed over on purpose — already imported, blank, or excluded by the rules. Not an error.
Failed
Rows that were meant to import but could not, each with a reason in the errors panel.

Worth knowing

  • The log is a record, not a control. Deleting an order does not remove it from here, and nothing here can be replayed — re-run the import from its own source page.
  • Rows count the source lines read, which is not the same as orders created. A large gap between the two is normal for a re-sync of an already-imported sheet.
  • Only the first five raw rows are kept for display, so this is a sample, not the whole file.
  • An automated run has no by name against it — that means the scheduled job did it, not a person.
  • Only the newest 100 runs are listed, so a busy day can push yesterday off the page.

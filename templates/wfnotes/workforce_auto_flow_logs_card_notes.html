The run history for one automation flow. Every time the flow fires — for real or as a test — a row is written here with what it did, how long it took, and what went wrong if it failed. This is where you come when someone says "the message never arrived": the row tells you whether the flow ran at all, and if it ran, which stage broke. The flow itself is edited and switched on or off from Automation Flows.

What you can do here

Flow strip
The bar under the header repeats what this flow is — its trigger, its action, and whether it is currently active or disabled.
Tallies
Success, failed, test and total counts across the flow's whole history, not just the rows shown below.
Result
The stage-by-stage trace of that run — config check, message render, connection check, send — each marked OK or failed.
Error
A short label guessed from the message (timeout, auth, not found, server error) plus the raw text underneath.
Duration
Milliseconds the whole run took. A long one usually means an outbound call waited on a timeout.
Back to Flows
Returns to the list, where you can edit, toggle or test-run this flow.

Status values

Success
Every stage passed. For a WhatsApp or webhook flow that means the message or call actually went out.
Failed
A stage raised an error and the run stopped there. The failing stage is named at the front of the error text.
Test
The run came from the Test button on the flows list rather than a real event.

Worth knowing

  • Only the 50 most recent runs are listed. The tallies above count everything ever recorded, so they will usually be higher than the rows you can see.
  • A test run of a WhatsApp or webhook flow is not a dry run — it really sends the message or calls the URL. Status, driver-assignment, notification and create-task actions are simulated only.
  • An empty log does not mean the flow is broken: if the flow or its trigger is disabled, or no matching event happened, nothing is written at all.
  • This page is read-only. There is no retry and no delete — fix the flow's settings and let it fire again, or use Test to reproduce the failure.

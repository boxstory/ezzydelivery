One client, one integration, one question: does the connection actually work? The left panel shows the credentials and URLs saved for this platform; the right panel shows what the client's store or sheet said when we last asked it. This is where a new integration is proved before it is switched on, and where you come back when a client's orders have stopped arriving. Approving the integration here is what makes it live for imports.

What you can do here

Test Connection
Calls the client's platform live and pulls back a handful of recent orders and products — or reads the sheet — then prints the raw response and the status code beside it.
Approve
Marks the integration as verified so it counts as a live connection for this business. The button flips to Revoke Approval once it is on.
Revoke
Takes the approval away again. The configuration is kept — only its verified state changes.
Config panel
Read-only here. Business, platform and the store or sheet URLs, with anything unset called out as Not configured.
Back
Returns to the API Configs list, which is where the URLs, keys and tokens are actually edited.

Reading the state

Approved
The integration is verified and treated as a live connection for this business.
Pending
Configured but not yet approved. A warning is shown on the panel until someone signs it off.
Ready
Nothing has been tested yet in this visit — not a verdict on the connection.
Connected
The platform answered and returned usable data.
Failed
The call did not come back clean. The response panel carries the reason — bad credentials, wrong URL, or the store refusing us.
Not configured
A required URL or endpoint was never filled in. Fix it on the API Configs page before testing again.

Worth knowing

  • The test is read-only against the client's store. It fetches a small preview and writes nothing to their system, so it is safe to run as often as you like.
  • Approving does not test, and testing does not approve. It is entirely possible to approve a connection that is broken — run the test first.
  • A green test only proves we can reach the store. Whether the orders come in correctly depends on the column mapping, which lives in Mapping Manager.
  • Shopify needs the .myshopify.com handle; a merchant's own domain is resolved to it where possible, and the test says so when it did.
  • Google Sheet integrations need a one-time server authorization. If that has never been done, every sheet test fails for that reason and not because of the client's sheet.

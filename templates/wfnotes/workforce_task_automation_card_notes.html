The rulebook for who a published delivery task goes to. Publishing a task never shows it to drivers by itself — it lands in Unassigned Tasks, where no driver can see it. The rules on this page get one look at it the moment it lands there: the first active rule that matches hands it to one driver or sends it to Public. A task no rule matches simply waits in Unassigned for staff.

What a rule does

When
Client, drop-off zone group, task type and delivery speed. Every condition you set must hold; one left on "Any" is ignored. A rule with no condition catches every task.
Then — driver
The task goes to that driver's Assigned tab and nobody else sees it. Only drivers with app access can be picked.
Then — Public
The task shows in the New tab of every driver with app access; the first one to take it gets it.
Order
Rules are tried lowest number first and the first match wins, so put narrow rules (one client) above broad ones (one zone, or everything).

When rules run

Automatically
Each time a task is published with no driver — Publish to Fleets, bulk publish, auto-import, return legs and return pickups.
On demand
Run rules on Unassigned now applies the active rules to everything already waiting — use it after adding a rule.
Never
After staff unassign a driver. That task stays in Unassigned on purpose until someone picks again.

Worth knowing

  • A driver rule is skipped while its driver has no app access (not approved, or access switched off) — the next rule gets the task instead. The table flags it.
  • Turning a rule off or deleting it never takes tasks back from the drivers it already gave them to.
  • Every task a rule routes says so on its order timeline, with the rule's name.

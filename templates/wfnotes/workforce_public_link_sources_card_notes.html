Some clients keep their orders on a web page rather than sending them to us — a published Google Sheet, a shared report, any page with a plain table on it. Each row here is one such link that we read on a schedule. The sync fetches the page, reads the first table on it, and drops the rows into Temp Orders as drafts for a human to review and import. Nothing here creates a real order on its own — that still happens on the Temp Orders screen.

What you can do here

Add source
Opens the form: pick the client, give it a label you will recognise, paste the public URL. Saving runs a sync straight away and tells you how many rows came in — or why it failed. Leaving the label blank auto-names it after the client.
Active switch
Saves the moment you flip it, no page reload. Off means the scheduled sync skips the link entirely while keeping the row and its history.
Delete
The bin icon, behind a confirm. Removes the link and its stored headers and mapping.
Open URL
The link in the URL column opens the client's page in a new tab — the quickest way to check a source is still reachable and still has a table on it.
Temp Orders
Where the synced rows land for review and import.

Reading the columns

Headers
How many column headings we saw the last time we read the page. A dash means we have never successfully read a table there.
Mapping
How many of the client's columns are wired to our order fields. Not set means the link cannot import anything yet — fix it in Mapping Manager, on the client's public-link tab.
Last Sync
How long ago we last read the page. A dash on an active source that has been around a while is a warning sign.
Orders
How many rows the last sync brought in — not a running total of orders ever imported from this link.

Worth knowing

  • A source with no mapping does nothing quietly — the sync runs, finds no mapping and returns zero rows without an error. If a client says orders are not coming through, check the Mapping column first.
  • Customer name, phone and address must all be mapped. If any of the three is missing the sync refuses to run for that source and reports the failure.
  • Only the first table on the page is read, and the URL must be reachable without a login. A page that needs sign-in returns the login HTML, not the data.
  • Rows arrive as drafts. An order that already exists with the same client order code is marked imported and left alone, so re-syncing does not create duplicates.
  • Deleting a source does not touch orders or drafts already created from it — those stay where they are.

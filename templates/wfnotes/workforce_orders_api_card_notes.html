A window onto a client's own shop. Pick a client and the page calls their connected platform — Shopify, WooCommerce or a Google Sheet — and shows the orders sitting there right now, next to whether we have already pulled each one into our system. Nothing here is our data until you import it. Only clients with an approved, verified integration are listed; what happened on previous runs is on Import History.

What you can do here

Pick a client
The row of buttons at the top. Each carries a tag for the platform it is connected to. Nothing loads until you choose one.
Show filter
All, Not Imported (your work queue) or Imported (what we already took).
Select rows
Tick the orders you want. Already-imported rows have no checkbox — they carry a green link to our order instead. Select all takes everything tickable on the page.
Import
Opens the wizard for the selection: review what you picked, check the field mapping, preview exactly what will be written, then confirm.
Verify step
Shows each order as our own database fields, with the source column it came from. You can correct a value inline before importing.
Column mapping
Sheets only. Wires each sheet column to an order field and saves it for that client, so every later import reads the same way.
Go to row
Sheets only. Jumps to a row number. The page opens itself near the last row you imported, which is usually where the new orders start.
Open our order
The green badge on an imported row links straight to the order it became.

Reading a row

Imported
We already hold this order. Matched by the platform's own order id, or for sheets by row number.
Paid
The customer has already paid the shop, so the driver collects nothing. The ledger shows COD as zero.
COD due
Not paid at the shop — this is the cash the driver has to collect at the door.
Shipping line
The delivery option the customer chose at checkout. Useful for spotting express or scheduled requests.
API Error
The platform did not answer. Nothing is wrong with our records — the shop's credentials, sheet sharing or the platform itself is at fault.

Worth knowing

  • This list is fetched live on every page load. It can be slow, and a row can disappear or change because someone edited it on the shop's side.
  • Importing pulls the order in one direction only. Inline corrections in the verify step are saved on our order and never written back to the shop or sheet.
  • Orders already imported are skipped by the wizard, so a re-run is safe — but for sheets the match is by row number, so reordering or deleting sheet rows can make an old order look new.
  • With no saved mapping, sheet columns are guessed. It usually works and sometimes puts a phone number in the wrong field — save a mapping for any client you import regularly.
  • Products are matched by name, and a close match is remembered as an alias for next time. Check the matching preview the first time you import for a client.
  • Imported orders land as normal orders needing review — importing is not dispatching.

Every automation flow on the platform, one per row. A flow joins a trigger ("order delivered", "task accepted", a webhook event) to a single action — usually a WhatsApp message, but it can also call an external URL, move a status, assign a driver or raise a task. The triggers themselves are catalogued on Auto Triggers; this page is where the rules built on top of them are switched on, tried out and audited.

What you can do here

Add Flow
Opens the builder — pick a trigger, add conditions, choose one action and configure it.
On/Off
Enables or disables the flow immediately, without a page reload. The Status badge follows the switch.
Config
View shows the flow's stored settings — message template, webhook URL, target status, and any trigger conditions — exactly as saved.
Test
Runs the flow once with sample data and shows a stage-by-stage result. The run is written to the flow's log as a test.
Edit
Reopens the builder for that flow.
Logs
Run history for that flow — successes, failures, tests, and the error text for anything that broke.
Delete
Removes the flow after a confirmation. The row disappears without reloading the page.

Trigger categories

WhatsApp
Order and task lifecycle events that exist to notify someone — the customer, the driver, the seller or staff.
Webhook
Events pushed in from the API side — task accepted or rejected, status updates, COD collected, documents uploaded.
System
Things the platform itself does — a staff approval, a status transition, a settlement — raised internally rather than by an outside call.

Status

Active
The flow will run when its trigger fires — provided the trigger is enabled too.
Disabled
Kept with all its settings but never executed.

Worth knowing

  • A flow runs only when both the flow and its trigger are enabled. Switching a flow on here does nothing if its trigger is off on Auto Triggers.
  • Test is not a dry run for the outward-facing actions: a WhatsApp flow really sends a message and a webhook flow really calls the URL. Status changes, driver assignment, notifications and task creation are simulated.
  • A test on a flow that sends to the customer or driver falls back to a placeholder number, so a green result proves the connection works — not that the right person was reached.
  • Deleting a flow also removes its run history. If you only want to stop it, switch it off.
  • New flows arrive here already switched on, so review the config before walking away.

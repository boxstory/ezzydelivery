The exception pile. Every order whose status has been set to reported lands here — something went wrong with it and someone flagged it for staff to look at. It is a worklist, not a workspace: the page shows you who and where, and you then act on the order through its delivery task. Newest reports lead, so the freshest problem is always at the top.

What you can do here

Go to Tasks
Opens the full delivery task list, which is where a reported order is actually reassigned, retried, failed or cancelled.
Paging
Fifty orders a page. There is no search or filter — work the list top-down, or find a specific order from the task list instead.

Reading a row

Client code
The reference the client's own system uses. It is what a client will quote when they ring about the order, so match on it first.
Customer
Name and mobile of the recipient — usually the first call to make on a reported order.
Created
When the order was raised, not when it was reported. An old date near the top means a long-running order that has only just gone wrong.
Second line
Each order carries a paler row underneath with its pickup point on the left and the customer's delivery address on the right.

Worth knowing

  • Nothing on this page changes an order. An order leaves the list only when its status stops being reported, which happens where the work is done — on the delivery task.
  • The list does not carry the reason for the report. That sits in the order's comments, so open the order or its task before ringing anyone.
  • An order can be reported while its delivery task is still live. Check the task's own status before assuming the delivery has stopped.
  • Reported is a staff-facing flag, not a customer-facing one — clients do not see this list, so anything they need to know still has to be communicated.

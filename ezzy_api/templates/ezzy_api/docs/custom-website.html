🧩 Custom Website Integration

Push orders straight from your own checkout into EzzyDelivery

How It Works

If your store is not on Shopify or WooCommerce, your website sends each confirmed order to EzzyDelivery itself. There is nothing to install and nothing for us to poll — when your checkout completes, your server makes one HTTPS POST to our order endpoint.

📋 The flow

  • Customer completes checkout on your site.
  • Your server posts the order JSON to /api/v1/store/orders/.
  • We reply with our order number — store it against the order.
  • The order lands in your EzzyDelivery dashboard as Hold for Review, and our team confirms it into a delivery task.
  • You can ask for the delivery status of any order at any time.

Authentication

Every request carries the API key EzzyDelivery issued for your store. Send it as a Bearer token (or in the X-API-Key header — both work):

Headers

Authorization: Bearer YOUR_API_KEY Content-Type: application/json

The key identifies your store, so you never send a business or account id in the body — orders can only ever be created under your own account. Keep the key on your server; never place it in browser JavaScript, a mobile app, or a public repository. If it leaks, ask us to rotate it.

Check your key works

GET /api/v1/store/ping/
curl https://ezzydelivery.qa/api/v1/store/ping/ \ -H "Authorization: Bearer YOUR_API_KEY" {% verbatim %}

Response

{ "success": true, "business": "Your Store", "account_status": "active", "can_create_orders": true, "scope": "write" }
{% endverbatim %}

Create an Order

POST https://ezzydelivery.qa/api/v1/store/orders/

Post one order per request, as a single JSON object.

{% verbatim %}

Request body

{ "orderNumber": "GOOEY-429869", "paymentMethod": "applepay", "customer": { "name": "Hind Alobaidli", "phone": "51060099", "area": "Doha", "street": "Al wahat street - alkhuraitiat", "buildingType": "Apartment", "buildingNumber": "31", "notes": "Big gate 3 go inside 31" }, "items": [ { "id": "smore", "name": "S'more", "qty": 2, "price": 35, "lineTotal": 70 } ], "subtotal": 70, "deliveryFee": 20, "total": 90, "createdAt": "2026-09-11T16:00:29.000Z" }

Response — 201 Created

{ "success": true, "duplicate": false, "message": "Order received", "order_number": "GOE181-29869-AB796", "client_order_code": "GOOEY-429869", "order_status": "to_review", "order_status_label": "Hold for Review", "cod_amount": "0", "cod_status": "online_paid", "delivery_status": "", "driver_name": "", "tracking_url": "" }
{% endverbatim %}

Save order_number — that is the EzzyDelivery reference your staff and ours will both quote.

Fields

FieldRequiredNotes
orderNumberYesYour own order reference. Must be unique in your store — it is what makes retries safe.
paymentMethodYescod / cash means the driver collects. Anything else (applepay, card, googlepay…) is treated as already paid.
customer.nameYesRecipient name.
customer.phoneYesQatar mobile. 51060099, +974 5106 0099 and 00974 51060099 are all accepted.
customer.areaYes*Area / district, e.g. Doha, Al Sadd.
customer.streetYes*Street name or number.
customer.buildingNumberYes*Building / villa number.
customer.buildingTypeNoApartment, Villa, Office…
customer.notesNoLandmark or delivery instruction. Shown to the driver.
customer.zoneNoQNAS zone number, if your checkout collects it. Speeds up our address verification.
customer.whatsappNoDefaults to the phone number.
items[]NoLine items: name, qty, price, lineTotal, optional sku. Up to 50 lines.
subtotalNoGoods value before delivery.
deliveryFeeNoWhat you charged the customer for delivery.
totalYes for CODAmount the driver must collect on a COD order. Falls back to subtotal + deliveryFee.
createdAtNoISO-8601 timestamp of the checkout.

* At least one address field must be present — area, street and building together give the driver a deliverable address.

🔧 Already have your own field names?

You do not have to rename anything. Send us one sample order payload and EzzyDelivery maps your field names onto ours — ref to the order number, buyer.mobile to the phone, basket[].title to the line items, and so on. Once that mapping is saved, post your payload exactly as your site already builds it.

Cash on Delivery

This is the one field to get right. paymentMethod decides whether the driver asks the customer for money:

paymentMethodWhat we do
cod, cash, cash_on_deliveryCOD amount = total. Driver collects and we settle it to you.
anything elseCOD amount = 0. The order is marked paid online; the driver collects nothing.

Sending a prepaid order with a COD payment method makes the driver charge your customer twice, so map this field from your real payment status, not from the cart.

Retries & Duplicates

If your request times out, send it again. We key each order on your orderNumber: the second call does not create a second delivery, it returns the order that already exists with "duplicate": true and HTTP 200 instead of 201.

This only works if orderNumber is unique per order on your side. Never reuse one for a different customer.

Check Delivery Status

GET /api/v1/store/orders/{orderNumber}/

Look an order up with your own reference (our order number also works). You get the whole order back — status, customer, lines, amounts, and the exact payload we received from you, so you can reconcile without keeping a second copy of what you sent.

{% verbatim %}

Response

{ "success": true, "order_number": "GOE181-29869-AB796", "client_order_code": "GOOEY-429869", "order_status": "publish", "order_status_label": "Published", "order_date": "2026-09-11", "cod_amount": "0.00", "cod_status": "online_paid", "delivery_status": "out_for_delivery", "delivery_status_label": "Out for Delivery", "driver_name": "Ahmed K.", "tracking_url": "https://ezzydelivery.qa/track/abc123.../", "delivered_at": null, "customer": { "name": "Hind Alobaidli", "phone": "51060099", "whatsapp": "51060099", "address": "Apartment 31, Al wahat street - alkhuraitiat, Doha", "zone": 26, "street": null, "building": 31, "area": "Al Khuraitiyat", "notes": "Big gate 3 go inside 31", "latitude": "25.3521...", "longitude": "51.4712...", "address_verified": true }, "items": [ { "name": "S'more", "sku": "", "qty": 2, "unit_price": "35.00", "line_total": "70.00" } ], "amounts": { "items_total": "70.00", "delivery_fee": "20.00", "cod_amount": "0.00" }, "package": { "description": "S'more x2", "qty": 2 }, "received": { "...the exact JSON you posted..." } }
{% endverbatim %}

Money is always a two-decimal string ("0.00", "70.00"). zone, area and the coordinates fill in once our team verifies the address — they are null while the order is still in review.

tracking_url appears once the delivery task is created — you can show it to your customer or put it in your confirmation email. Poll this endpoint no more than once a minute per order; for push updates, ask us to set up a webhook to your server instead.

Errors

HTTPMeaningWhat to do
400A required field is missing or invalidRead error in the body and fix the payload. Do not retry unchanged.
401Missing, wrong, or disabled API keyCheck the Authorization header. Contact us if the key was revoked.
403Account is suspended or awaiting approvalContact EzzyDelivery — orders cannot be created until the account is cleared.
404Order not found (status lookup)Confirm the reference you posted.
429Too many requestsBack off and retry after a short pause.
500Something failed on our sideRetry — the idempotency rule protects you from duplicates.

Going Live

✅ Checklist

  • Key stored server-side, in an environment variable.
  • GET /api/v1/store/ping/ returns can_create_orders: true.
  • One real test order posted and visible in your dashboard.
  • paymentMethod mapped from the real payment result.
  • Our order_number saved against your order.
  • Failed posts logged and retried — never dropped silently.

Need help? Contact EzzyDelivery support with your store name and the order reference.

🔐 Authentication

Authenticate API requests with your business API key

How It Works

Every API key belongs to a single business. When you call the API with your key, the server identifies your business automatically — you only see and manage data that belongs to that business. Cross-business access is not possible with an API key.

Base URL: https://ezzydelivery.qa/api/v1/

Authentication Methods

The API accepts your key in either of two headers. Pick whichever fits your client:

1. Bearer Token (recommended)

Send your key in the Authorization header:

Authorization: Bearer ezz_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

2. X-API-Key header

Or send it as a dedicated header:

X-API-Key: ezz_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Both methods are equivalent. Do not send both at once. All requests must use HTTPS.

Generating an API Key

Step 1: Open API Settings

  1. Log in to your EzzyDelivery business account
  2. Go to Business Dashboard → Settings → API
  3. Scroll to the API Keys section

Step 2: Click "Generate Key"

Fill in the optional fields:

  • Key Name — a label so you can identify it later (e.g. "Production", "Mobile App")
  • Expiration Date — leave empty for no expiry

Step 3: Copy your credentials

After generation, the success modal shows:

API Key:    ezz_key_qxGkCBdoxJRUevjHiO8KbPswY2QkGqRK
API Secret: ezz_sec_a8Jt7Hn4kPoYzVrM1Bx9LqWdF6CpEiNs

⚠️ Important: The full key is shown only once. Copy and store it immediately in a secrets manager or environment variable. You can always revoke and regenerate if lost.

The API Secret is reserved for future signed-request features and is not required for the standard Bearer / X-API-Key flow described on this page.

Using Your API Key

cURL — list orders
curl -X GET "https://ezzydelivery.qa/api/v1/business/orders/?limit=10" \
  -H "Authorization: Bearer ezz_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
Python (requests)
import os, requests

headers = {
  "Authorization": f"Bearer {os.environ['EZZYDELIVERY_API_KEY']}"
}

r = requests.get(
  "https://ezzydelivery.qa/api/v1/business/orders/",
  headers=headers,
  params={"limit": 50}
)
r.raise_for_status()
print(r.json())
JavaScript / Node.js
const res = await fetch(
  "https://ezzydelivery.qa/api/v1/business/orders/?limit=50",
  {
    headers: {
      "Authorization": `Bearer ${process.env.EZZYDELIVERY_API_KEY}`
    }
  }
);
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const data = await res.json();

Business Scoping

An API key resolves to exactly one business — the business it was generated for. Every request is automatically filtered:

  • GET /api/v1/business/orders/ returns only orders for your business
  • GET /api/v1/business/clients/ returns only your business's clients
  • GET /api/v1/business/tasks/ returns only your business's delivery tasks
  • GET /api/v1/business/dashboard/ returns stats for your business only

Attempting to access another business's resource by ID returns 404 Not Found — the server treats it as if the resource does not exist.

Managing Your Keys

Disable a key

  1. Go to Settings → API → API Keys
  2. Find the key in the list
  3. Toggle it to Inactive
A disabled key stops working immediately. Use this if a key is compromised.

Replace a key

  1. Generate a new key (with the same name if you want)
  2. Roll it out to all your integrations
  3. Disable or delete the old key once nothing is using it

Expiry

If you set an expiration date when generating, the key stops working at that timestamp. Expired keys return 401 Unauthorized — generate a fresh one to continue.

Errors

Status Meaning
401 Missing, invalid, inactive, or expired API key
403 Key is valid but the action is not allowed for this business
404 Resource doesn't exist — or belongs to a different business
429 Rate limit exceeded (1000 requests/hour per key)

Security Best Practices

✓ Do

  • Store keys in environment variables or a secrets manager
  • Use HTTPS for every request — never plain HTTP
  • Use a separate key per integration (mobile app, ERP, scripts) so you can revoke individually
  • Set an expiration date for short-lived integrations
  • Disable any key you suspect is leaked, then generate a replacement

✗ Don't

  • ✗ Commit API keys to git — use .env + .gitignore
  • ✗ Embed keys in client-side JavaScript or mobile app bundles
  • ✗ Reuse the same key across unrelated systems
  • ✗ Send keys in URL query parameters — they get logged

Test Your Authentication

Quick verification with cURL:

Verify your key works
curl -i "https://ezzydelivery.qa/api/v1/business/orders/?limit=1" \
  -H "Authorization: Bearer ezz_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
✓ Expected: HTTP 200 with a JSON body like {"count": N, "orders": [...]}. If you see 401, double-check the key value and that it's active in Settings → API → API Keys.
Interactive testing:
  • Swagger UI — try endpoints in the browser. Click Authorize and paste your key (without the Bearer prefix).
  • ReDoc — clean, read-only reference
  • OpenAPI Schema — raw JSON for IDE tooling

Environment Variables

Recommended: keep keys out of source code.

.env
EZZYDELIVERY_API_KEY=ezz_key_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
EZZYDELIVERY_API_URL=https://ezzydelivery.qa/api/v1
Python
import os
from dotenv import load_dotenv

load_dotenv()
API_KEY = os.environ["EZZYDELIVERY_API_KEY"]
API_URL = os.environ["EZZYDELIVERY_API_URL"]
Node.js
require('dotenv').config();
const API_KEY = process.env.EZZYDELIVERY_API_KEY;
const API_URL = process.env.EZZYDELIVERY_API_URL;

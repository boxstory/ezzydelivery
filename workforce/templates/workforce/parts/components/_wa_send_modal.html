{% comment %} Purpose: Shared "send WhatsApp from the EZZY number" composer — one modal any staff page can drop in. Used by: workforce driver_detail.html, crm/lead_detail.html, forms/pricing_inquiry_detail.html (include with wa_section + wa_to + wa_name). Notes: Sends through workforce:whatsapp_send_routed, so the number AND the channel come from the section's sender route on the Auto Triggers page — never from the staff member's own phone. Pass the optional wa_session to pin one conversation to a specific number (the CRM lead page does; the endpoint checks it against the numbers we own). Pass wa_message to offer a starter body as a paste chip — the calling view renders it from a core.message_templates key, editable on the AI Config Messages tab. Pass wa_reminder (+ wa_reminder_label) to add a SECOND page body to the picker: everything this record has not given us yet, written out for the recipient — the driver application sections still open, or the quote answers still missing. It sits first in the list because it is the one body only this record can produce; pass '' and the option is simply absent, which is what "nothing missing" must look like. Per-button data-wasend-reminder overrides it, the way data-wasend-message does. Trigger it from any button carrying data-wasend-open plus data-wasend-to / data-wasend-name. The box opens EMPTY on purpose: a pre-filled template is the one people send by accident. Above it sits a paste row instead: the clipboard, the last message this staffer actually sent (localStorage, per section, this browser only), and a template picker fed by workforce:whatsapp_composer_templates — every enabled body registered for this section, rendered with the recipient's and staffer's names. Placeholders that endpoint cannot know are left as {placeholder} and Send refuses a body still carrying one. From is a dropdown: it defaults to the section's route (or wa_session when the page pins one) and lists every number we own that has a WAHA session, so a staffer can send one message from another line without changing the route. Picking a number forces the WAHA channel — see core.whatsapp_utils.resolve_send_target — and the endpoint re-validates the choice. The footer keeps a wa.me deep link for the same number, so replacing a page's old deep-link button with this composer never costs anyone the "open it on my own phone" route. Design: the navy routing plate at the top is the point of the modal — this send is routed, and which line it leaves from is a decision, so From → To is drawn as one routed path rather than two label/value rows. It is a CSS grid, not flex: the sender value and the select swap places depending on how many numbers we own, and flex wrapped that into the channel chip reading as part of To. Everything below the plate stays white, hairline and grey — see the wasend block in workforce.css. Both selects carry data-no-select2: the dashboard-wide Select2 enhancer otherwise swallows them (it hides the real control at width:1px and its change event never reaches a plain addEventListener, so picking another sender silently did nothing). Send result: pressing Send covers the panel with wasend__result. A send that lands shows "Sent" and closes the window on its own; a send that fails stays put with the reason and two ways out — Back to message (the typed body is still there) or Close. The inline status line under the box is for pre-flight problems only (empty body, unfilled {placeholder}, clipboard refused), so "you cannot send this yet" never looks like "this did not send". {% endcomment %}

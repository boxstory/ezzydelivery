{% comment %} Purpose: The shared staff-list filter bar — client, search, period presets, apply/clear, applied chips, page size. Used by: any staff list page; page-specific controls come in through `extra_filters_template`. Notes: Ids are the pgf_* set the pg-filter handler in workforce.js drives — do not rename them per page. WHY THIS EXISTS Each list had hand-built its own bar, so the same control drifted page to page: different ids, different widths, one page with raw date boxes where every other had presets. The core lives here once; a page adds only what is genuinely its own. PARAMS (all optional unless noted) filters REQUIRED. The view's `filters` dict. Reads .search, .business (list), .datePreset, .dateFrom, .dateTo. all_businesses Client dropdown options. Omit to hide the client filter. client_multiple True renders the client picker as multi-select. search_placeholder Placeholder for the search box. Omit to hide search. show_period Default True. The Today/Yesterday/3 Days/... presets. extra_filters_template >>> THE PER-PAGE HOOK <<< Path to a template rendered at the end of row 2, inside the form, with the full page context. Put page-specific controls there (status pickers, DL code, sort, …). It receives everything the page view passed. extra_actions_template Same idea for the button cluster on row 1 (export, etc). applied_chips List of {label, value, remove_url} for the applied strip. applied_hint Plain sentence for the applied strip (used when a page defaults a filter it wants to state, e.g. "last 3 days"). per_page_choices e.g. [10, 25, 50, 100]. Omit to hide the page-size control. per_page Current page size. reset_url Where the clear button goes. Defaults to request.path. {% endcomment %}

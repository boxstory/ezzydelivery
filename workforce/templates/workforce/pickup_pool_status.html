{% extends "wf_dashboard_base.html" %} {% load static %} {% comment %} Purpose: Staff pickup pool — every first-mile pickup task, filters, assign/reassign, return-to-pool, cancel, delete, bulk actions Used by: workforce_views.pickup_pool_status at /workforce/pickups/ Notes: The status filter defaults to "open", which hides handed_off rows (finished first-mile legs); "All statuses" brings them back. The date window defaults to the last 7 days (?days=7); a From/To pair (?date_from/?date_to) overrides the preset and shows as "Custom range"; the two boxes are hidden under every other preset and revealed by picking it. When the window hides a pickup that is still active, ppl__windownote says how many and links to all-time — the window must never bury live work. "Create pickup" (hero, right) is the repair hatch for an order that never got a first-mile leg — imports save the order with no pickup location, so the create-time gate bails. It looks the order up, offers the client's active non-fulfilment-centre locations, writes the chosen one onto the order and runs the same create_pickup_task_if_needed service. Refusals are shown in the service's own words (fulfilment centre / pickup disabled / inactive) — there is no override. The client cell carries a pickup-location dropdown on any leg still in pending/accepted/in_progress/arrived — changing it posts pickup_staff_relocate, which moves the pickup AND its order to that address and notifies an assigned driver. From 'collected' onwards the driver holds the goods, so the cell falls back to plain text. Only the client's active non-fulfilment-centre locations are offered. Assign allowed in pending/accepted/in_progress/arrived; "Back to pool" (accepted→pending) only before collection. Cancel closes the first-mile leg only (order + delivery task untouched) and is refused on already-closed legs. Delete removes the row and is superadmin-only (can_delete_pickups) and refused once collected. Row checkboxes (shift-click ranges) drive the bulk bar, which posts pickup_ids[] to the same assign/unassign/cancel/delete endpoints. Driver picker reuses fleet search. The Timeline button expands a third row per pickup and pulls workforce:pickup_timeline_card — the same _pickup_leg_card.html strip the task detail page renders — once per row, on demand (the cancel lookup and the GPS count are a query each, so it is never rendered inline). Hero filters carry data-no-select2 and are enhanced locally instead: the global staff-dashboard enhancer forces width:100% + light chrome, which stacked the fields and collapsed the navy hero. The local init uses width:'auto' and the ppl__pick skin. The page-notes card (wfnote__, shared) sits under the hero, hidden on load; the hero help button toggles it via the delegated handler in workforce.js. {% endcomment %} {% block title %}Pickup Pool - Staff Dashboard{% endblock title %} {% block content %} {% csrf_token %}

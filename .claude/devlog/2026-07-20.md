# Dev Log — 2026-07-20

## 14:34 — Fix COD collection status stuck on "Pending" after admin confirms Received & Verified
The "Confirm Received & Verified" button on a `cod_collection` (CODC-) transaction drawer correctly saved `is_received`/`is_verified` on that transaction, but the transactions list status badge for `cod_collection` rows only checked an unrelated settlement transaction (`delivery_task.cod_submission_txn`), which never gets touched by that button. So confirming a collection never flipped its badge past "Pending". Updated the badge condition in the template to check the transaction's own `is_received`/`is_verified` first, falling back to the existing submission-txn and deposited-refs checks.

**Files:** `workforce/templates/workforce/fleet_transactions.html`

## 15:15 — Sync COD corrections to driver wallet/COD-in-hand and lock quoted COD after collection
The "Edit COD" correction flow (`fleet_task_cod_correct`) updated the ledger transaction and per-method running balances but never adjusted `driver.wallet_balance` or refreshed `driver.cod_in_hand`, so those fields — read directly by the fleet app's finance summary and driver profile pages — went stale after any cash COD correction. Added a wallet_balance delta (mirroring the cash-only debit rule in `WalletService.record_transaction`, careful not to double-count when a brand-new ledger row is created) plus a `WalletService.sync_cod_in_hand()` call after every correction. Separately, the general task edit page (`delivery_task_edit`) had no `cod_amount_locked` check at all, unlike every other place that edits `Order.cod_amount` — any staff member could silently rewrite the quoted COD after the driver already collected, with no warning and no ledger sync. Added the same lock guard used in `update_task_status` (blocks non-superadmins once locked, with a message pointing them at the dedicated Edit COD flow). Also swapped the two fleet templates that read `driver.wallet_balance`/`driver.cod_in_hand`/`driver.available_wallet`/`driver.wallet_usage_percentage` directly to use the already-live-computed `wallet_status` context instead, so those screens can't show a stale cached value even in other edge cases.

**Files:** `workforce/views.py`, `fleet/templates/fleet/parts/fleet_finance_summary.html`, `fleet/templates/fleet/parts/driver_profile_mobile.html`

## 20:56 — Zone map: Edit Point mode
The zones map page only offered "Edit Polygon" — there was no way to correct a zone's center point. Added an Edit Point mode: a new `update_zone_pin` AJAX endpoint (staff-gated) saves a zone's lat/lng, and the map now has an Edit Point button in both the marker popup and the zone table that makes the marker draggable with a Save/Cancel toolbar over the map. Saving updates the marker, label, popup, table row, and neighbour-line coordinates in place.

**Files:** `delivery/views.py`, `delivery/urls.py`, `templates/delivery/zone_map.html`, `delivery/static/delivery/css/delivery.css`

## 21:18 — Pickups PWA: transfer sheet stuck open + broken empty state

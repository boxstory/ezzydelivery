## 00:06 — WhatsApp Alerts redesigned as the delivery run
Rebuilt /business/settings/whatsapp-triggers/ from a five-column settings table into a vertical
run of stages. The reasoning: the six triggers are not options in a list, they are the stages of
one parcel's journey, and Delivered/Failed are alternative endings rather than steps five and six
— so the stages hang off a hairline rail whose last two nodes are squared and set off to the side
as a branch. Each stage is now a card with the message full width instead of crushed into a fifth
column beside four mostly-empty ones.

The message is set in mono because it is a template, not prose: the {tokens} read as the code they
are and the line breaks match what lands in WhatsApp. Kept the box wide on purpose — the longest
default line is 88 characters, so narrowing to the usual 80-character measure would falsely wrap
template lines the author never wrote.

Two Brand Kit collisions found by reading matched rules out of the browser rather than guessing.
The client dashboard fixes every checkbox at 1rem with !important
(templates/static/business_dashboard_base.css), so a Bootstrap switch cannot render here; the
stage state is a house checkbox plus the words "Sending"/"Not sending", with the whole label as
the hit target. And since that checkbox already fills yellow when checked, the rail node reads in
navy instead — yellow stays spent twice, on the checkbox and the Save button.

Order parameters moved from a slab above the list into a sticky column beside the editor on
screens ≥1200px, open by default there and collapsed on narrower ones. Added a per-stage "Our
wording" button, which matters more now the default is no longer visible as a placeholder. Picked
Up and Start Ride render dashed and say plainly that nothing is sent for them. No control was
removed. 26 tests pass; 14 live behaviour checks (dirty tracking, token insert at caret, reset,
save round-trip, no clipping, no overflow) pass on the deployed page.

## 01:11 — Driver codes are now unique, admin-only and in ABC12 format
`Driver.driver_code` had no unique constraint and one of the two signup paths generated a 6-digit code with no collision check at all, so two drivers could in principle end up sharing a code. Added `unique=True` (migration 0047, data was already clean at 671 drivers with zero duplicates), dropped the now-redundant `driver_code_idx`, and moved both signup paths onto a single generator in the new `fleet/codes.py`. New codes are 3 letters + 2 digits (e.g. ABC12) drawn from an alphabet with O, I and L removed so a spoken or handwritten code cannot be confused with 0 and 1 — existing numeric codes are left untouched since drivers already quote them. `Driver.save()` now refuses to change an existing driver's code unless `allow_code_change=True` is passed, which only `DriverAdmin.save_model` does, and an empty code is normalised to NULL so blanks do not collide under the constraint; `driver_code` was also marked read-only on both API driver serializers.

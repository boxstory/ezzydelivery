## 09:47 — Charges to Collect: the receivable leg (billing clients for delivery charges)
Until now a delivery charge could only be recovered by withholding it from a COD payout, so a
prepaid seller — who hands back no COD — could never be billed at all; `WalletService.record_charge`
existed but was called from nowhere and there was no invoice model. Built the missing leg: a
"Charges to Collect" desk listing every completed delivery (prepaid and COD together) whose fee no
payout has recovered, which issues a `BusinessChargeInvoice` with one frozen line per delivery plus
hand-added lines, books the revenue, and takes payments against it (partial, full, void). Wired the
two legs so a fee can only be collected once: the payout desk now shows an invoiced delivery as
"Invoiced" and stops withholding its charge, and `billable_tasks()` drops anything a payout already
withheld. Sellers get a read-only copy at /business/finance/invoices/ plus an Invoices link on their
finance dashboard; staff can print the A4 invoice or WhatsApp the client a link. 12,580 QAR across
10 accounts was sitting uncollectable before this. 8 new tests; fleet suite 199/199 green.

## 17:15 — Input-hardening pass across every form and request-data path

Audited all 47 form classes and the raw `request.POST` surface, then closed the gaps in three
phases. No SQL injection existed (everything goes through the ORM, and the one raw-SQL site
parameterises correctly), but output encoding and input validation had real holes.

**Phase 1 — XSS and uploads.** Added `core/json_utils.safe_json`, which escapes `< > &` the way
Django's own `|json_script` does and returns a SafeString, and swapped it into all 30 `json.dumps`
context variables that get inlined into `<script>` blocks (driver names, customer addresses, pickup
labels and mapping data were all reaching those blocks unescaped, so a stored `</script>` payload
would have executed). Fixed three non-JSON `|safe` sites too: the auto-flows config map, the
temp-orders `data-raw-row` attribute, and the blog JSON-LD — the last was emitting a Python dict
repr, so it was invalid JSON-LD and search engines were dropping it. Found and fixed a second,
DOM-side XSS in the same temp-orders modal, where imported sheet cells were interpolated straight
into `innerHTML`. Created `core/validators.py` and attached extension + size validators to all 18
upload fields; there had previously been no `validators` import in any models.py, so the four bare
`FileField`s accepted arbitrary content at arbitrary size. Wired `django-ratelimit` (installed but
never used) onto the four public marketing forms at 5/hour per IP.

**Phase 2 — validation floor.** Added `core/forms_base.SanitizedFormMixin`, which strips control,
zero-width and bidi-override characters from submitted text before field cleaning, and mounted it on
all 47 forms (passwords and secrets are excluded so they reach validation byte-for-byte). Replaced
`fields = '__all__'` in the three fleet forms with explicit allowlists — the blocklist had been
leaking `driver_meta`, which holds the staff-verified `registration_location` the Location Review
queue depends on, plus the `to_be_notified` broadcast toggle. Added `core/request_data.parse_post`
for the ~1,400 raw POST reads that have no form, and bounded all 50 `int(request.GET/POST...)` sites,
each of which returned a 500 on non-numeric input and several of which had no upper bound on
`per_page`/`limit`.

**Phase 3 — SSRF and exports.** Routed the merchant-supplied `site_api_url` through the existing
`core.net_guard.validate_public_url` (our server fetches that URL during API test and import, so it
was an SSRF lever at loopback, private ranges and the cloud metadata endpoint). Added
`core.exports.safe_csv_writer` and swapped it into all 10 CSV export writers to neutralise
spreadsheet formula injection.

46 new tests in `core/tests_security.py`, all green; full run 549 tests. Six failures in the wider suite are
pre-existing branch work in `orders/signals.py`, `delivery/signals.py` and `business/views.py` —
none in code this touched.

## 17:55 — Council review of the hardening pass: 1 critical regression fixed, 2 claims withdrawn

Ran a 10-agent adversarial council (new `/llm-council` skill) over the six gaps reported after the
hardening pass. It found a **critical regression the pass itself introduced**: `stage_keys` was
converted to `safe_json()` at `workforce/views.py:23803`, but `temp_auto_stages.html` iterates that
variable with `{% for %}` as well as embedding it in a script block. Django iterated the 99-character
JSON string character by character, rendering 99 junk columns, and because `_write_auto_stages`
defaults any missing key to `True`, a single checkbox click silently enabled every auto-import stage
for that business — including auto-publish and send-WhatsApp. Fixed by keeping the list in context and
adding a separate `stage_keys_json`; the other 29 conversions were checked for the same dual-use and
are clean.

Also fixed two silent data-corruption regressions: `_INVISIBLE_CHARS` was stripping U+200C/U+200D, which
destroys Persian/Arabic ZWNJ and breaks emoji sequences (narrowed to bidi overrides + zero-width space
+ BOM), and `normalize_qatar_phone` let the `00974…` dial form through unnormalised, creating a third
stored phone format.

Two of the six reported gaps did not survive review: the `float(request.POST)` claim was a grep
artifact (those lines are inside a try/except with a coordinate clamp two lines below), and the
20,000-char truncation ceiling is harmless (largest production value is 3,829 chars). Council also
surfaced higher-severity pre-existing issues than the gaps themselves — an unauthenticated lead-data
leak, a WhatsApp-driven stored XSS, and the fact that the new rate limits run on LocMemCache and are
therefore largely decorative. Those are logged for the next pass, not yet fixed.

4 new regression tests; `core/tests_security.py` now 50, all green.

## 18:40 — Fixed the full council finding list (13 items) + 3 self-inflicted regressions

Worked through the council's prioritised list. Two findings needed the plan changed after checking
the facts on this box:

- The council's rate-limit fix assumed "Redis is already running for Celery". It is not — port 6379
  refuses connections, `redis-server` is inactive and `CELERY_BROKER_URL` is unset. Used a
  PostgreSQL-backed `CACHES['ratelimit']` alias plus `RATELIMIT_USE_CACHE` instead, so counters are
  shared across the 4 gunicorn workers and survive the mandatory HUP. Before this the public form
  limits were per-worker and wiped on every deploy — effectively decorative.
- The council suggested adding `warehouse` to `GATED_NAMESPACES`. Checked first: 65 of 66 warehouse
  routes are unclassified in `core/departments.py`, and that namespace fails closed, so flipping it
  would have locked every staff member out of the whole warehouse section. Left it alone.

Also found the council's own one-word warehouse fix was wrong: `BusinessTeamProfile` has
`team_status`, not `status`, so renaming the import alone would still have failed silently into the
same bare `except`. Fixed properly, but then discovered 34 object lookups in `warehouse/views.py`
resolve a bare pk with no tenant filter — so repairing the lookup turns seller access ON across all
of them at once. Corrected the tenant scoping (stock levels were filtered by shared warehouse rather
than by business), then put seller access behind `WAREHOUSE_SELLER_ACCESS_ENABLED = False` until
those endpoints are scoped; whether sellers should reach warehouse operations at all is a product
call.

Fixed: lead-database leak (`inquiry_preview` was `@login_required` only — any driver could walk all
123 pricing leads); stored XSS via WhatsApp-controlled MIME echoed as `Content-Type` (now an
allowlist + `as_attachment` + nosniff); `OrderSerializer` mass assignment (62 writable fields → the
COD/verification/attribution cluster is now `read_only`, FKs are tenant-checked, creates pin
`order_status='to_review'`); upload validation enforced imperatively at the 4 real upload endpoints
since `objects.create()` never calls `full_clean()`; client filenames rebuilt as `<uuid>.<ext>`;
`MEDIA_EXTENSIONS` widened after measuring the 598 archived files (the old list omitted `oga`, 166
WhatsApp voice notes); SSRF DNS lookup gated on `changed_data`; two open redirects; `.env` newline
injection; AI-conversation IDOR; the 9 real `innerHTML` sinks; and regressions R5 (prefix-blind
mixin — the one form configuring the knob was the one form where it did nothing), R6 (decimal price
silently saved as 0) and R7 (`+974` phones getting a stray quote in client exports).

Deleted `core/request_data.py` — zero call sites, and its header claimed adoption it never had.

`core/tests_security.py` now 60 tests, all green.

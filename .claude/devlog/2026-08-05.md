# Dev Log — 2026-08-05

## 18:40 — Fix: "Linked" was shown for a session nobody had scanned yet

Reported: `FleetAdmin4545` shows "Scan QR with WhatsApp on your phone" on the
WAHA dashboard, but the Instances page showed it green as **Linked**. Real bug,
mine. The `waha_state` check only asked whether the session name appeared in
WAHA's session list — and WAHA lists a session the moment it is *created*, long
before a phone has scanned its QR. Existing was being read as connected.

Added a `pending` state: the session exists but is not `WORKING`
(SCAN_QR_CODE / STARTING / FAILED / STOPPED). It renders amber "Not connected"
with the reason — "Waiting for a QR scan" plus a deep link to that session's
dashboard tab, or the raw state for the other cases. `linked` now requires
`status == 'WORKING'`.

The dashboard's routing panel had the same flaw one layer up — `mapped` only
meant "a waha_session is configured", so a section pointing at an unscanned
session still displayed as sending from that number. `section_routes()` now also
returns `status`/`live`, and a mapped-but-not-live row warns with the session
state instead of showing the phone. WAHA being unreachable is deliberately NOT
treated as dead in either place, so a transient outage doesn't paint every
correctly-configured row as broken.

Verified against the real current state rather than fixtures: WAHA reports
`FleetAdmin4545 status=SCAN_QR_CODE me=(none)`, the Instances cell now reads
"Not connected — Waiting for a QR scan — open the dashboard ↗", and the panel
shows "Orders & Delivery Tasks → 97466124545 — session scan_qr_code" with the
other three still green. 48 whatsapp tests pass (7 new, covering unscanned,
FAILED, WORKING, and WAHA-unreachable for both surfaces).

## 19:20 — Redesign: WhatsApp Instances console (Brand Kit ledger)

Design pass on /workforce/auto-triggers/whatsapp-instances/. Audited the live
page in headless Chromium first rather than from the source, which turned up six
measured Brand Kit violations: table body at 12px (floor is 0.8rem), Bootstrap's
`<code>` shipping candy pink #d63384, the row Edit button rendering as raw yellow
text on white (1.68:1 — the exact "button that isn't a button" failure), a grey
`thead` where the recipe calls for the navy ledger band, four competing status
pill colours per row against the swatch+text rule, and yellow used five times in
one view against a budget of about two.

Rebuilt as a ledger. The signature is the transport lane: vertical hairlines
that run from the header through the body, dividing identity / Evolution / WAHA.
That is structural rather than decorative — a number has two independent paths,
either can be up while the other is down, and "which system does this column
belong to" was the actual confusion this page caused earlier today. Status
became swatch+text (filled dot for a live state, ring for configured-but-idle),
identifiers went to mono ink, and row actions became real bordered controls at
2.1rem. Every column, control and field was kept; nothing was hidden.

Two things only measurement could have found. `.table thead th` is forced to
grey by an `!important` in brandkit-overrides.css, and `tbody td` is forced to
0.75rem by an `!important` in **orders.css**, which loads on every staff page —
so the navy header and the legibility floor both needed explicit `!important` to
restore, with comments saying why so they don't get "cleaned up" later.

Also caught myself twice. The default row had both a yellow edge flag and a
DEFAULT label in a dedicated column — same fact twice, and over the yellow
budget, so the flag went. And an apparent mobile horizontal-scroll bug was a bad
metric on my side: `documentElement.scrollWidth` counts descendant scroll-
container content, so it read 759 on a 390 viewport. Checking whether the page
*actually* scrolls (max scrollLeft 0, body.scrollWidth 390, zero unclipped
overflowing elements) showed there was nothing wrong. The frame did move from
the table to the scroll wrapper as part of chasing it, which is the more correct
structure regardless.

Verified: 48 whatsapp tests pass; header now white-on-navy and body 13px by
measurement; the edit modal opened in a real browser and submitted unchanged
with every field round-tripping (label, instance name, WAHA session); served CSS
curled back from the live domain to confirm the CDN has the new rules.

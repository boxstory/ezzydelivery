# Dev Log — 2026-08-20

## 17:50 — Staff status popup now captures the reason (like the driver app)
The "Update Task Status" popup on the workforce delivery-task detail page had no reason field, so a staff-side Failed / Rejected / Cancelled left the task with no explanation while the driver app forced one. Added the same reason picker the driver's Failed sheet uses (rendered from `DeliveryTask.FAILURE_REASON_CHOICES`) plus a notes box; it appears for failed/rejected/cancelled/dropsownlost (required) and non_reachable (optional). The view now validates the key, saves `failure_reason` / `failure_notes` (mirroring into `rejection_reason` for reject/cancel), and passes the reason label into the order timeline note. Also added a "Reason on Record" card to the page so the driver's or staff's reason is visible, and three tests covering required/recorded/mirrored reasons — WfDeliveryTaskTest 17/17 pass.

## 21:51 — Stock Adjustment: "Adjust by ±" mode for damage write-offs
The adjustment sheet only accepted a counted total, so writing off one damaged unit meant reading the on-hand figure and typing the total minus one by hand — easy to get wrong, and stale if stock moved while the page sat open. Added a mode switch above the sheet: "Count total" (unchanged behaviour) or "Adjust by ±", where you type the change itself — `-1` for a damaged unit, `+3` for found stock — and the new quantity is shown per row. The delta is applied to the live locked row inside the transaction, and a deduction that would take the shelf below zero is refused by both the browser and the view, naming the product and its actual on-hand. The posted field is now `qty[]` with a `counted[]` fallback so a page left open across the deploy still works, and the ledger note records "(write-off)" vs "(count)".

Verified end-to-end against a real stock row inside a rolled-back transaction: deduct -1, over-deduct, deduct +3, zero no-op, count mode, negative count, legacy `counted[]` payload and a bogus mode all behaved correctly, and the row was left untouched at 28.

## 22:14 — Fix: default-location stock sheet was reading the wrong bin
Reported as "cannot deduct more than is on hand" on a product that visibly had 2 units. The stock-levels API parsed the location with `safe_int(..., default=0, minimum=1)`, and safe_int clamps UP to minimum — so an absent location became location id 1, a real bin. With "Default Location" selected the sheet was reading someone else's shelf: 0 on hand for everything, and the true default-location stock reported as "Other Locs". Changed the floor to `minimum=0` so absent/garbage resolves to None. Also made Other Locs actionable — the API now returns which bins hold the stray units, the figure is a button that switches the sheet to that bin, and the stray hint names the locations instead of just counting them.

Verified against the reported product: default location now reads 2 on hand, a bin reads 0 with "Default Location: 2" in Other Locs, and a -2 damage write-off posts `adjust_out -2, 2 → 0` (rolled back).

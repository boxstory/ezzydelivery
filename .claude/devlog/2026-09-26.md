# Dev Log — 2026-09-26

## 04:46 — Staff bulk edit page for order location and delivery fee
New staff page at /workforce/orders/bulk-edit/: a grid where each row has inline zone/street/building, lat/lng, pickup location and fee inputs, plus a "fill ticked rows" bar and a "fee back to rate card" button. Save sends only the changed fields. Each order commits on its own with the same rules as order_edit: a typed fee is pinned 'manual', and task dl_price follows unless the charge is invoiced or paid out. It also copies the new address and pin onto the driver's address row (order_edit never did), geocodes a changed address from QNAS within a time budget that stays under nginx's 60s limit, and logs each change to the order timeline. Delivered/returned orders can still have their fee fixed but their address is locked. Entry points: Orders sidebar (desktop + mobile) and a "Bulk Edit" button in the All Orders selection bar.

**Files:** `workforce/views.py`, `workforce/urls.py`, `core/departments.py`, `workforce/templates/workforce/orders_bulk_edit.html`, `workforce/static/workforce/js/orders-bulk-edit.js`, `workforce/static/workforce/css/orders-bulk-edit.css`, `workforce/templates/workforce/parts/sidebar/orders.html`, `workforce/templates/workforce/parts/dashboard_sidebar_workforce_mob.html`, `workforce/templates/workforce/parts/lists/orders_list_view.html`, `workforce/tests_orders_bulk_edit.py`, `.claude/docs/09-workforce-fleet/staff-url-departments.md`

## 04:58 — Fee column on the staff seller page Orders tab
The Recent Orders table on /workforce/sellers/<id>/#orders now shows each order's delivery fee, with where it came from (rate card, set by staff, imported, or not set). A new "Edit Location & Fee" button opens the bulk edit grid filtered to that client.

**Files:** `workforce/views.py`, `workforce/templates/workforce/seller_detail.html`

## 05:06 — Seller page Orders tab lists every order, returned included
The Orders tab on /workforce/sellers/<id>/ used to show only the 10 newest orders. It now lists all of the client's orders, including returned and cancelled ones, 50 to a page on its own `orders_page` parameter. Status chips with counts (All, Hold for Review, Ready, Published, Delivered, Returned, Cancelled) filter the list via `?ostatus=`. Returned orders get a warning-tone badge, and the status label uses its display name. The tab opens automatically when the URL carries the pager or status parameter. The Overview's recent-orders timeline is unchanged.

**Files:** `workforce/views.py`, `workforce/templates/workforce/seller_detail.html`, `workforce/static/workforce/css/workforce.css`, `templates/wf_dashboard_base.html`

## 05:14 — Seller Orders tab: order date under the order, delivered date under the status
On the seller page Orders tab, the separate Date column is gone. The order date now sits on a second line under the order number, and delivered/returned orders show their completion date under the status badge. A returned order never gets `delivered_at`, so its date comes from its customer-bound leg's `completed_at` (annotated in the view).

**Files:** `workforce/views.py`, `workforce/templates/workforce/seller_detail.html`

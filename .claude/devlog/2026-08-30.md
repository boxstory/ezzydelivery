# Dev Log — 2026-08-30


## 01:12 — Column width control on the delivery sheet
Line-1 chips in the Columns panel are now sized to their share of the printed row and carry a width control: a % field you can type into and a divider on the chip's right edge you drag like a spreadsheet column edge (the space comes out of the next column, so the row still adds up). The lane shows a running total with a "Fit widths to 100%" helper, and Apply sends the numbers through as a new `?widths=key:pct` parameter. The widths reach the page as a data attribute and are applied as `--w-<key>` custom properties, never as inline style — the stylesheet's per-column rules became `width: var(--w-key, <default>)`, so a sheet printed with JavaScript off still lays out exactly as it did before. Starting values are measured off the printed table rather than duplicated in Python, so there is no second copy of the numbers to drift.

**Files:** `workforce/views.py`, `workforce/templates/workforce/dl_tasks_print_sheet.html`, `workforce/static/workforce/css/dl-task-sheet.css`

## 10:58 — Seller Transactions: sortable headers, row selection, bulk actions, filter chips
Reworked the ledger into a proper console. Every DB-backed column now sorts server-side
(order code, date, customer, COD amount, COD status, order status) through the existing filter
form, so a sort keeps the filters and covers the whole list, not the 50 rows on screen; a plain-
English sort picker sits in the toolbar beside the exports. Distance stays unsortable on purpose
— it is measured per page, so ordering on it would rank a page against itself. Added a checkbox
column with select-all, a navy selection bar showing the count and the running COD total, and
four bulk actions on the picked rows: copy codes, export selected as CSV, print selected, clear.
All four are read-only — COD state changes stay on the settlement screen — and a second sort key
(-id) keeps paging stable inside ties. Filters gained a search box (order code, client code,
customer, phone) and a COD-state multi-select alongside the existing controls; nothing was
removed. An applied-filter strip now names what is narrowing the list, each chip linking back to
the same page minus that one filter.

Four real bugs surfaced while building it. The Order Status column tested for 'completed' and
'in_progress', neither of which exists in ORDER_STATUS_BY_CLIENT, so 151 of 153 rows — every
delivered order included — printed as a yellow "pending" badge; the branches now follow the
model. The money column carried an inline style (forbidden) and is now a mono tabular class. The
applied-filter chips were invisible because `.ftr__chip` is already the filter-builder chip on
Fleet Transactions and is display:none until switched on — renamed to `.ftr__applied`. And the
table body rendered at 12px because orders.css ships a global `tbody td { font-size:.75rem
!important }`, under the 0.8rem console floor. Also aligned the filter controls at 36px, lifted
the hero button off 27px, and cut the page to one yellow (the hero's Settle button) by moving
Apply to navy and the exports to outline.

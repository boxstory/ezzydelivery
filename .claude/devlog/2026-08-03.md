## 00:40 — Temp-order sync now honours the Mapping Manager
The temp orders page ignored the Shopify tab entirely: `_shopify_order_to_row()` had a hardcoded field list reading `shipping_address` only, and the review grid read dict rows with the csv mapping block. ## 22:23 — Auto-import no longer blanks mapped address/phone (Shopify + Woo)

## 20:47 — Cancelled/delivered orders no longer leave a claimable pickup in the driver pool

A driver reported that order EDN132-F0016-AB217 was still sitting in the Pickup tab's Available list even though its delivery had been cancelled. Two things were wrong. The pool query only looked at the PickupTask row itself — pending, unclaimed, business in the driver's directory — and never at the order or its delivery task, so a pickup stayed claimable until something explicitly cancelled that row. And almost nothing did: the only writer was the Order post_save when order_status flips to cancelled, so cancelling the delivery task alone left the pickup untouched. The pool now excludes pickups whose order is cancelled or delivered, and whose latest delivery task is cancelled/delivered/partial (latest via subquery, so an old cancelled task plus a live retry still shows). Failed tasks deliberately stay in the pool since they can be retried. The delivery-task post_save now cancels the pickup when the leg ends, the two signal-free queryset cancel paths in orders/views.py pull the pickup explicitly, and bulk_update_order_status now saves order rows one by one (so history/notifications/pickup cleanup actually fire) and scopes its task cancel to the orders it really changed.

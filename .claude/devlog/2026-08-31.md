## 22:14 — Link colour declared outright so Bootstrap cannot win it back
bootstrap-custom.min.css ships its own `a { color: rgba(var(--bs-link-color-rgb)) }`
at the same specificity as the base rule, so leaving the colour to the variable
alone was fragile. brandkit-overrides.css now declares `color` (and the hover
colour) directly on `a`, and it loads after Bootstrap in includes/head.html, so
the later declaration wins. Bootstrap's `a:not([href]):not([class])` reset is
carried forward so non-links stay inert.

**Files:** `webpages/static/webpages/css/brandkit-overrides.css`, `templates/includes/head.html`

## 23:07 — Resolve WhatsApp Maps short links server-side in the shared-location fields
The "Paste / Drop Shared Location" inputs used to give up on a `maps.app.goo.gl` link and tell staff to open it once and paste the long URL, because the browser cannot follow that redirect (Google sends no CORS header on goo.gl). Added `core/views_location.py` — a signed-in-only `/api/resolve-location/` endpoint that allow-lists the hostname with urlparse before any outbound request, reuses the existing `extract_coords_from_text()` resolver, caches each pin for 24h and rate-limits to 60 lookups/min per user. `qnas-verify.js` now falls back to that endpoint whenever the regex finds no coordinates and the text looks like a short link, then re-enters the normal path with the resolved "lat, lng", so all six paste/drop fields plus the bulk-order table resolve pins automatically. A pin outside Qatar is still applied but flagged with a warning badge rather than silently rejected.

**Files:** `core/views_location.py`, `core/urls.py`, `workforce/static/workforce/js/qnas-verify.js`, `orders/templates/orders/order_add.html`, `templates/wf_dashboard_base.html`, `templates/business_dashboard_base.html`, `workforce/templates/workforce/parts/delivery_task_edit.html`

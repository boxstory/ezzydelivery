## 13:57 — Driver PWA: Location Check diagnostics panel
Investigated ezzy.dr001 reporting "location permission denied" on a Samsung S24 installed PWA. Server side was clean (Permissions-Policy already allows `geolocation=(self)`, HTTPS fine), so the block is device-side — but the app only showed a dead-end toast with no way to tell which of the three layers (browser site permission / Android app permission / device location service) was refusing. Added a "Location Check" card to driver Settings that reads `navigator.permissions.query`, takes a real fix, and maps the failure code to the exact setting to change, including Samsung Internet's separate per-site permission store and Android's approximate-vs-precise location trap. Also recorded the last positioning error in EzzyGPS so it can be surfaced instead of only logged.

## 18:33 — Data repair: wrong products on origeneral llc bulk-import orders 1956-1960
Investigated why every order from ImportLog #458 (`bulk_import_sample 17.xlsx`) showed the same item. The bulk importer feeds the free-text `package_desc` into `_match_product_by_name` alongside the real `product_1` column; because all 5 rows shared the description "Reward Vip Watch For Men" and the seller had a product literally named `reward` at the time, the loose substring fallback matched that one product on every row, while the actual variant cells (BLACK/BLUE/GREEN) matched nothing and were silently dropped. Corrected the three wrong OrderItems against the Excel raw_data: 1957 -> Blue, 1958 -> Green, 1960 -> Green (1956/1959 were already Black and correct). No stock was reserved or delivered on these orders, so the warehouse ledger was untouched. Code fix for the importer not applied yet.

**Files:** none (database-only repair via shell)

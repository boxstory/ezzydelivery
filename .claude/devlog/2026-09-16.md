# Dev Log — 2026-09-16

## 12:59 — Refresh button on the CRM lead chat panel
Added a Refresh button to the WhatsApp Conversation panel on the CRM lead detail page. It posts to a new endpoint that pulls that one lead's chat straight from WAHA (same upsert the inbox Resync uses, scoped to the chat ids the lead's stored messages actually route on, falling back to the phone JID when nothing is stored yet), then hands back the re-rendered bubbles so the panel updates in place — no page reload, so the scroll position and open linker survive. The message bubbles moved into a partial that both the page and the endpoint render. Tested live on lead 744: it picked up 2 messages the webhook had never delivered (27 → 29). New URL classified in core/departments.py for ops/marketing/admin.

## 13:08 — Seller roster card: bracket the pending-orders working
The pending-orders figure on the seller-transactions roster card printed the working and its
total as two adjacent numbers ("82 + 9" immediately followed by "91"), so staff read it as a
single value, "82 + 991". Wrapped the working in brackets and widened the gap after it, since
both sides are digits and size/colour alone were not separating them the way the QAR unit does
on the other half of the card. No view or query change — the figures themselves were correct,
and the roster already excludes COD paid out on a CODCS payout invoice.

**Files:** `workforce/templates/workforce/seller_transactions.html`, `workforce/static/workforce/css/seller_roster.css`

## 13:20 — Seller roster: COD to pay and total deliveries in the page header
Put the book totals in the Seller Transactions header: COD to pay sellers, and total deliveries.
First built this as a per-card band of lifetime figures, which was the wrong read — the useful
number is the total across all sellers, not per account — so that was reverted and the card is
back to exactly the pending position it carried before. COD to pay is the Ezzy leg only (cash
still with a driver has not reached us to be owed, and a payout run cannot touch it), summed
from the roster rows already in memory so the header is by construction the sum of the column
beneath it. Deliveries needed its own aggregate since the COD rows are filtered to
cod_collected=True and cannot see a prepaid job.

**Files:** `workforce/views.py`, `workforce/templates/workforce/seller_transactions.html`, `workforce/static/workforce/css/seller_roster.css`

## 11:08 — Pickup Automation: floating save bar replaces per-row Save
Removed the per-row Save button (and its table column) from /workforce/pickup-automation/. Each row now tracks its own baseline, so changing the auto-pickup switch, pool mode or after-collection rule marks that row dirty (cream tint + yellow edge) and raises a floating save bar at the bottom with the changed-rule count, Discard and Save changes; the bar stays hidden until something actually changes and disappears again if the edit is reverted. Saving posts each dirty row separately to the existing per-business endpoint, holds "Saved" for a beat, and a beforeunload guard warns about unsaved rules. Verified in a headless browser as staff: bar appears on change, hides on revert, save persists to the DB.

**Files:** `workforce/templates/workforce/pickup_automation_list.html`, `workforce/static/workforce/css/workforce.css`, `templates/wf_dashboard_base.html`

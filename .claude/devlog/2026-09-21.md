## 08:16 — Fix CRM WhatsApp inbox Resync "Unexpected token '<'" error

## 23:53 — Default message becomes the value; one Save button in the header
The WhatsApp Alerts boxes now hold the message as an editable value rather than a placeholder.
The catch that shaped the design: an unedited box posts our default text back, and storing it
would freeze a per-client copy that no future improvement to the default would ever reach. So
`whatsapp_triggers_save` compares the submitted body against the current default and stores ''
when they match — the existing "follow the default" state. Clearing a box does the same thing, so
emptying it hands the trigger back to our wording; the Active switch remains the way to stop a
message going out.

The six per-row Save buttons and the Action column are gone. A single "Save changes" button lives
in the navy header and only appears once a row actually differs from what loaded — undoing an edit
by hand hides it again — alongside an "N unsaved changes" readout and a beforeunload guard. It
posts every changed row in one atomic request to the new `/settings/whatsapp-triggers/save/`
endpoint (the old per-row `toggle/` endpoint and view were removed). Caught one bug in testing:
`refreshSaveButton()` in the fetch `.finally()` was wiping the "Saved" line, so it now only clears
its own unsaved-changes text.

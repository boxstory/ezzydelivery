## 03:15 — Send log was missing WAHA traffic (the reason panels looked empty)

The Logs panels stayed empty because the logging added yesterday only wrapped the
Evolution client, while almost all real traffic leaves over WAHA — 383 outbound messages
in 36 hours, none of them recorded. `send_waha_text` writes its own WhatsAppMessage row
and never touches the Evolution path, so healthy busy numbers rendered as "No sends
recorded yet".

WAHA sends now log too, attributed to the instance that owns the session
(default → EzzyWhatspp, Ezzy6000 → Ezzy-COS, FleetAdmin4545 → Ezzy-Fleet). A WAHA failure
deliberately does NOT feed the Evolution failover health marker — the two bridges fail
independently, and letting a WAHA problem mark an Evolution socket dead would cause false
failovers. Added a `channel` column to WhatsAppSendLog (migration 0026) and the panel now
shows Evolution API vs WAHA per line, since one number can send over either. Raised the
per-instance retention from 50 to 200 rows: at a few hundred messages a day, 50 was only a
couple of hours of history.

## 11:00 — Warehouse: delivered orders were never deducting stock (missing warehouse link)
Vénora's inventory page overstated on-hand by 28 units: 18 orders delivered 08-02→08-12 wrote zero `ship` transactions. Root cause was that the business had no `SellerWarehouseLink` row, and `_direct_deduct_stock` returned early on that condition with only a buried `logger.warning`, so every delivered order silently left `quantity_on_hand` untouched. Changed the no-link case to fall back to whichever warehouse actually holds the product's stock (safe — the query is already scoped by `product=item.product`, which is owned by the business) and log at ERROR level, and escalated the unmet-quantity branch to ERROR as "unrecorded shipment" since that is the state that makes on-hand drift upward. Also restored the missing link for Vénora (warehouse WH-001-SDN, existing PickupLocation 113 was updated in place, no merchant-visible change) and backfilled 26 corrective `ship` transactions for the 28 delivered units, bringing on-hand to 188/196/92/196/93/186/200/86 with `ProductInventory` mirroring correctly. Verified by exercising `_direct_deduct_stock` in a rolled-back transaction both with and without the link — both now deduct −4. Note: the receive form's date field is cosmetic, it only lands in `InventoryTransaction.notes`, so backdating a receipt does not replay deliveries since that date. Also audited sitewide: business 83 (MarkFairWhale) has the same missing-link condition, 4 stock rows / 110 on-hand / 33 delivered orders, not yet corrected. The 3 failures in `orders.test_warehouse_inventory` were confirmed pre-existing (they assert a removed deduct-on-`picked_up` / `reference_type='delivery_task'` design).

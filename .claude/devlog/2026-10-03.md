# Dev Log — 2026-10-03

## 04:12 — WA inbox: quick label buttons + two-line filter bar
The /waha/wa-chats/ filter bar is now two lines: search + Persons/Groups on the first, then "Driver" and "Leads to follow" quick buttons followed by the label dropdown on the second. The buttons resolve their label by name, drive the existing label dropdown (second click clears), and stay hidden on a number without that label.

**Files:** `whatsapp/wa_chats_view.py`

## 04:13 — WA inbox: contact cards no longer print raw vCard text
WhatsApp contact-card messages arrive from WAHA with the raw vCard as their body, including a multi-KB base64 PHOTO line, and the inbox printed it verbatim (seen on chat 97430330067 in the default session). The server now parses the vCard into name + phone (single and multi_vcard), blanks the raw body, and the bubble shows a compact 👤 contact card; the chat-list preview shows "👤 Name". Deleted messages and call logs, which rendered as empty bubbles, now show a short italic notice.

**Files:** `whatsapp/wa_chats_view.py`, `whatsapp/waha_views.py`, `whatsapp/management/commands/backfill_waha.py`

## 04:19 — WA inbox: removed the session pill from the chat header
Removed the "Session" status button (`#wa-session-link`) from the conversation header on /waha/wa-chats/, along with the loadSessionStatus() poller that only fed it (it hit WAHA every 30s) and its CSS. The session chip and the "Session health & QR" link in the session modal are unchanged.

**Files:** `whatsapp/wa_chats_view.py`

## 04:42 — WA inbox: search finds chats by any part of the phone number
Searching the inbox for part of a number (e.g. "303300") showed "No chats." because the search only filtered the chat pages already loaded, and most 1:1 chats are @lid ids that contain no phone at all. Added a `?find=1&q=` lookup on the contact directory (phone digits or saved/WhatsApp name, session-scoped, marketing-only label chats excluded) that the search box calls after a 250ms pause; matching chats light up in the list and directory hits not loaded yet are added as openable rows.

**Files:** `whatsapp/wa_chats_view.py`

## 04:50 — WA inbox: search inside message text
The inbox search box now also searches stored message text (3+ characters) on the current number and lists matches in a "Messages" section under the chat results, WhatsApp-style: chat name, time, a snippet around the match, "You:" on our own messages. Clicking a result opens that chat. Results come from the WhatsAppMessage table (newest 30, contact cards and system rows skipped, marketing-only label chats excluded); messages stored against a phone are remapped to the chat's @lid id so the click opens the live thread.

**Files:** `whatsapp/wa_chats_view.py`

## 04:52 — WA inbox: message-search result jumps to the message; labels on result rows
Clicking a "Messages" search result now opens the chat and scrolls to that exact message, paging in older history (up to 15 pages) until it appears, then flashes its bubble; if it is not in the history a short error says so. Messages are matched by the id's trailing hash so phone- and lid-keyed copies of the same message both match. Message result rows in the left list now show the chat's WhatsApp label chips like chat rows do.

**Files:** `whatsapp/wa_chats_view.py`

## 05:03 — WA inbox: chat list kept stopping on scroll; added Load more on failure
When one chat-list page failed (WAHA slow/down → 502, which error.log shows happening), the client read it as "0 chats fetched", marked the list exhausted and never loaded another chat until a page reload. A failed page now leaves the offset alone, retries on a timer (3s → 30s backoff) while the reader is at the bottom, and shows a "Couldn't load more chats. [Load more]" bar at the end of the list. Also a scroll that landed during the 30s refresh is now picked up when that refresh finishes. Verified in headless Chromium with an injected 502.

**Files:** `whatsapp/wa_chats_view.py`

## 05:15 — WA inbox: reply to a message (quote-reply)
Each bubble on /waha/wa-chats/ now has a ↩ Reply button (shows on hover; always faintly visible on touch screens). Clicking it opens a "Replying to …" bar above the composer, and Esc or × cancels it. Sending passes the message's full serialized id to WAHA `sendText` as `reply_to`, which the send view checks against an id pattern. Messages that quote another one (WAHA `replyTo`) now show the quoted text at the top of the bubble, and clicking that strip scrolls to and flashes the original if it is loaded.

**Files:** `whatsapp/wa_chats_view.py`

## 05:45 — WA inbox: attachments, voice notes, reactions, forward, edit/delete, number check, archive/unread
Built WAHA features 1–7 into /waha/wa-chats/. All of them are in WAHA Core since 2026.6.1 and the docs mark them supported on WEBJS. Bubbles get Reply / React / More actions: forward to up to 5 chats, and edit (15 min) or delete-for-everyone on our own messages. The composer gets 📎 attach (also paste and drop) and 🎤 voice notes, and the page now sends `microphone=(self)` because the site-wide Permissions-Policy blocks the mic. The header gets ⋮ Chat with Mark unread and Archive/Unarchive, and the list gets an Archived view. A typed number with no chat is checked once against WhatsApp, only on search / new chat. Reactions are stored in the new `WhatsAppReaction` table, because WAHA's message list does not say which emoji was used. The webhook has a handler for `message.reaction`, but it only receives events once that event is added to WAHA's `WHATSAPP_HOOK_EVENTS`. Edit/delete also update our stored row, which wins over WAHA's copy; a deleted row has its `message_type` set to 'unknown' so it shows "This message was deleted".

**Incident (fixed):** inserting `_store_reaction` moved `waha_webhook`'s `@csrf_exempt` / `@require_http_methods` decorators onto the new function. The webhook returned 403 (CSRF) from 05:35:03 to 05:35:53 UTC and was fixed at 05:36. WAHA gave up on only 4 `session.status` events, which our webhook ignores anyway; no message events were lost.

Tests: 26 new tests in `whatsapp.tests_inbox_actions` (153/153 whatsapp tests pass). A headless Chromium run of the live page passed 27/27 checks, with every write intercepted so nothing was sent.

## 06:10 — WA inbox: any image goes as a photo; sent attachments no longer show blank
A WebP picture saved from a website went out as a document, because only JPEG/PNG were sent as photos. Any still image (WebP, HEIC, GIF, BMP, AVIF…), and any photo over 16 MB, is now re-encoded to JPEG with Pillow (pillow_heif for iPhone photos), the longest side capped at 2560 px, and sent with sendImage. SVG, and anything Pillow cannot open, still goes as a document. Separately, our own fresh sends showed as empty bubbles: the webhook does not store `fromMe` messages, and the live list comes with `media.url = null`. Live media messages now point at a new `media-live/` route, which saves the message from WAHA (downloadMedia=true), archives its file and streams it. Resync and this route now share one `store_live_message()` helper. Documents show their file name, and a media message whose file is gone says "(file not available)" instead of drawing a blank bubble. 7 new tests (160/160 whatsapp); checked against the real WebP message, which now streams and is archived.

**Files:** `whatsapp/wa_chats_actions.py`, `whatsapp/wa_chats_view.py`, `whatsapp/chats_urls.py`, `whatsapp/tests_inbox_actions.py`

# Dev Log — 2026-08-25

## 08:42 — CRM board: lane strip bottom pinned to the viewport bottom
The kanban lane strip (`.crmb__lanes`) sized itself once on load/resize, so anything that
moved afterwards — opening the notes card, filter chips wrapping to a second row, the
marketing rail loading — pushed its bottom edge (and its horizontal scrollbar) below the
fold, where `<main style="overflow:hidden">` makes it unreachable. `sizeLanes()` now
re-measures from the strip's live top offset on a queued animation frame, driven by a
ResizeObserver on the console plus resize/scroll/visualViewport events, so the bottom edge
always ends exactly at the bottom of the screen. Writes are skipped when the value has not
moved, so the observer cannot loop back on itself.

## 09:18 — Driver applicants excluded from the device gate; ProfilePicture FK fix
The one-device rule was blocking driver onboarding. `Profile.is_driver` is set the moment someone submits the join-driver application (core/views.py:602), not when they are approved, so an applicant counted as a driver and every onboarding page — the application form, its verification screen, /join_us/ — bounced to the new-device OTP gate. Reproduced it in a test first: all four URLs returned 302 to /fleet/device/verify/. The rule now keys off an approved Driver row instead of the profile flag, so applicants are never gated and the OTP starts at their first login after approval. While reproducing this, found a pre-existing bug in the same path: three places created a ProfilePicture with `profile_id=request.user.id`, using the User id as the Profile id — two independent sequences, so /join_us/ either attached the picture to somebody else's profile or raised an IntegrityError. Now uses `profile.id`. Note: an intermediate full-suite run showed 34 errors that were purely another session's concurrent test run sharing the test DB; clean re-run is 352/352.

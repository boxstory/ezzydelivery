## 13:58 — Capture the driver's position at the moment of a status change
Status changes were pinned to whatever GPS ping happened to be stored last, which is not the same as where the driver was when they tapped. Measured over the last 400 status points: 95 (24%) had no position at all, and of those that did the stamped fix ran to a median 11s old but a maximum of 2.9 days — stamped as "driver at this status change". First-mile pickup stages had nothing stored at all; the timeline could only guess from the nearest trail ping. Added `EzzyGPS.stamp()` to the driver PWA: it takes a fix and stores it before a status-changing request goes out, capped at 6 seconds so a driver at a door never waits on GPS, falling through unchanged when GPS is unavailable. Wired into every driver action that moves a status — accept, start ride, status update, complete/delivered, failed, postpone, partial delivery, and all the pickup actions including barcode collect. Server-side, `_create_task_status_point` no longer stamps a fix older than 15 minutes, and `latest_for_driver(within_minutes=…)` now bounds on when the fix was *taken* rather than when it arrived, so a replayed offline ping can't pose as a current position. The timeline also pins the "on the way" and "arrived" pickup stages, which were previously the only stages with no pin.

## 18:40 — Tried CSS-styled native dropdown lists, reverted
Attempted to style the open list of native `<select>` elements — the one part of these fields CSS normally cannot reach — using `appearance: base-select` with `::picker(select)`, wrapped in `@supports` so older browsers were unaffected. `CSS.supports('appearance','base-select')` reports true in Chrome 145, but a minimal probe showed the popup still painting natively: the selected row stayed browser-blue and the surface ignored radius, shadow and padding even though computed styles reported the new values. It also swapped the custom chevron on the closed control for the UA's solid triangle, which is a visible regression. Removed the whole block; the field boxes keep the styling from the earlier pass (0.5rem radius, 2.25rem box, 0.85rem text, mono dates/times, yellow focus).

Conclusion for anyone revisiting this: a native select's popup cannot be restyled with CSS today. Styled dropdown items require Select2, which the portal already loads and which this stylesheet already themes — but `main_dashboard_scripts.html` deliberately keeps posting-form selects native, because Select2 hides the real control and a `required` field then fails HTML5 validation as "not focusable". On the Add Order form that rules out Delivery Speed (required=True); COD Status, Preferred Time Slot and Occasion are optional and would be safe.

## 18:56 — Waybill barcode: full label width + vector, for thermal scanning
The waybill barcode shared a footer row with Ref/Date/Pieces/COD, so it only got about two thirds of the label, and it was a PNG the browser then resampled down — which greys out the bar edges and is why it stopped scanning on a low-quality thermal print. The barcode now has its own full-width row under a single meta line, and is generated as inline SVG (new `generate_barcode_svg` in delivery/label_utils.py, module string taken straight from python-barcode's Code128 so the symbol is bit-identical) with preserveAspectRatio="none" + shape-rendering="crispEdges", so the printer rasterises the bars itself at its own DPI. Bars are also taller, and print-color-adjust forces solid ink instead of dither. Measured in headless Chromium: the narrow module went from ~1.6 to 2.36 dots at 203dpi on an 80mm roll, 3.0 on 4x6/A6, 2.7 on A4 — 58mm rolls are still only 1.7 dots, which is under the 2-dot floor Code128 needs, because the order number is 17 characters.

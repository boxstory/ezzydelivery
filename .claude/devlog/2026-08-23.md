# Dev Log — 2026-08-23

## 09:24 — First-mile pickup: retry when a location arrives late + staff "Create pickup"
Order GLM562-J1005-AB587 had no pickup task because Shopify quick-import saves the order with no
pickup location, so the create-time gate bailed on `no_pickup_location` — and that hook only ever
ran once, on order create. The location it later picked up (`WH: EzzyDelivery FC- Sudan`) was a
fulfilment centre, which is a second hard block. Added a second-chance path in the order post_save:
when `pickup_location` goes from empty to set on a non-terminal order, the same
`create_pickup_task_if_needed` service runs again (source=`location_assigned`); the service is
already idempotent so a re-save can never make a second leg.

Also added a staff repair hatch at `/workforce/pickups/create/` — a "Create pickup" button on the
pickup pool that looks an order up, offers that client's active non-fulfilment-centre locations,
writes the chosen one onto the order and opens the leg. Refusals are reported in the service's own
words (fulfilment centre / pickup disabled / inactive) with no override flag. Mode and disposition
still come from Pickups → Pickup Automation. Used it to open the legs for GLM562-J1003-AB585,
-J1004-AB586 and -J1005-AB587; backlog is now zero. 11 new tests, `delivery.tests_pickup` 58/58 OK.

## 09:45 — Staff can change a pickup's location from a dropdown on the pool
The pickup pool showed the seller's pickup address as plain text, so there was no way to correct a
leg pointing at the wrong place — the only lever was editing the order, and that left the existing
PickupTask on the old address. The client cell now carries a dropdown of that seller's active,
non-fulfilment-centre locations on any leg still pending/accepted/in_progress/arrived; changing it
posts `pickup_staff_relocate`, which moves the pickup AND its order together and notifies an
assigned driver that the address changed. From 'collected' onwards the cell falls back to text.

The move lives in one service (`relocate_pickup`) so both directions use it: the new endpoint, and
an order post_save hook that carries an open leg across when staff change the location on the order
edit page instead. Refusals are worded (collected, wrong client, inactive, fulfilment centre). A leg
parked on a fulfilment centre or a retired address shows that address as a disabled selected option
so the row never claims the pickup is somewhere it is not. 7 new tests, suite 65/65 OK.

Date: 2026-01-16
Issue: Product images not displaying in card view

═══════════════════════════════════════════════════════════

ROOT CAUSE:

The Product model had ImageFields with STRING default values:
  - product_image: default="business/product_images/product_image_default.jpg"
  - brand_logo: default="business/product_images/brand_logo_default.jpg"

Django ImageFields don't work properly with string defaults!
When an ImageField has a string default, Django's URL generation fails
because it expects a file object, not a plain string path.

═══════════════════════════════════════════════════════════

FIXES APPLIED:

1. ✓ Removed string defaults from Product model (product/models.py:132-135)
   - brand_logo: Now null=True, blank=True (no default)
   - product_image: Now null=True, blank=True (no default)

2. ✓ Cleared existing string values from database
   - Updated 114 products with default product_image strings
   - Updated 115 products with default brand_logo strings
   - Set empty ImageFields to '' (empty string)

3. ✓ Applied migration: product.0005_remove_image_defaults

4. ✓ Custom template filters handle empty images correctly
   - safe_image_url filter (core/templatetags/custom_filters.py)
   - Returns default image path when ImageField is empty
   - Works with both empty and uploaded images

5. ✓ Removed aggressive onerror handler
   - product_card2.html no longer replaces images with box icon
   - Prevents false-positive error handling

═══════════════════════════════════════════════════════════

HOW IT WORKS NOW:

When a product has NO uploaded image:
  → product.product_image is empty ('')
  → safe_image_url filter returns: /media/business/product_images/product_image_default.jpg
  → Default image displays correctly

When a product HAS an uploaded image:
  → product.product_image contains the file reference
  → safe_image_url filter returns: /media/product_images/[filename]
  → Uploaded image displays correctly
